Google Cloud's Spanner Removes Cumulative Mutation Limits for DML Transactions

Previously, Spanner capped changes at 80,000 "mutation mods" per transaction. Now, this 80,000 limit applies to individual DML statements (INSERT, UPDATE, DELETE) rather than the entire transaction, allowing a single transaction to contain any number of DML statements as long as each individual statement is under the limit. This change simplifies applications requiring high data consistency and scalability, particularly for complex operational workloads like fraud detection in e-commerce.

Context: This is a significant technical improvement for developers using Google Cloud's Spanner, enhancing its flexibility and scalability for complex transactional workloads. It directly impacts web and cloud developers by simplifying application logic, as they no longer need to artificially split larger transactions to comply with previous cumulative limits. The change is compatible with existing client libraries, ensuring a seamless transition and reducing development overhead.
